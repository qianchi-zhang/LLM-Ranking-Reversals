# 历史项目计划（归档整理版）

## 1. 文档性质

本文件是对早期项目计划的归档整理版，用于保留最初的研究设想、任务拆分和方法框架。它代表的是“最初计划”，不是当前仓库的最终真实实现。

如果本文件与当前代码、数据产物或 [README.md](/d:/ST5230/LLM-Ranking-Reversals/README.md) 不一致，应以当前实现为准。

## 2. 原始研究问题

项目最初围绕以下问题展开：

- 在语义不变、仅做表面 prompt 改写时，模型分数是否会变化；
- 当测试子集变化时，模型相对排名是否仍稳定；
- 这些变化是否足以导致 ranking reversal。

## 3. 最初计划中的实验设计

### 数据集

最初计划使用三个自动可评分的多项选择 benchmark：

- MMLU
- ARC-Challenge
- HellaSwag

### Prompt 扰动

最初计划对每道题生成 4 类 task-preserving prompt：

- `minimal_instruction`
- `benchmark_style`
- `minor_nonsemantic` 或相近表述
- `order_phrasing_variation`

后续真正实现中，模板命名和措辞略有调整，但整体思路保持一致。

### 预期流水线

最初计划即采用四阶段结构：

1. 数据抽样与 prompt 生成
2. API 调用与模型推理
3. 答案解析与评分
4. bootstrap 统计分析与可视化

## 4. 最初计划中的模型方案

早期方案中曾考虑过以下模型组合：

- GPT 系列
- Claude 系列
- Gemini 系列
- Llama 系列

需要特别说明：

- 这只是历史计划；
- 当前仓库最终实际跑通并进入分析的数据，模型集合为 `GPT-4o-mini / Gemini-2.0-flash / Qwen-2.5-7B / Llama-3.1-8B`；
- 因此最终报告不应再按本历史计划中的 Claude 方案表述实验设置。

## 5. 最初计划中的分工思路

项目最初计划按四个模块拆分：

- 数据与 prompt 生成
- API 调用
- 评分解析
- 统计分析

这种模块化拆分后来基本延续到了当前仓库结构中。

## 6. 与当前实现的主要差异

当前真实仓库与早期计划相比，主要差异包括：

- 最终分析模型集合发生了调整；
- Phase 2 的历史完整结果来自 notebook 运行，后续才对齐成脚本；
- 当前仓库已经包含完整产物，不再是仅有计划的空骨架；
- 当前标准复现入口已经收敛为 `run_pipeline.py` 和分阶段脚本。

本文件只适合作为以下用途：

- 解释项目最初的研究出发点；
